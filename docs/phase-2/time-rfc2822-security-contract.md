# RFC 2822 递归栈耗尽修复与 Rust 1.85

本增量承接 rbatis 接入契约和正式工作区现存的 time 版本告警。RustSec RUSTSEC-2026-0009/CVE-2026-25727 指向 RFC 2822 注释的递归解析；上游 0.3.47 引入深度上限，但该版本及关联组件要求 Rust 1.88，不能直接替换项目的 1.85 基线。维护补丁以完整原发布版 0.3.45 为基础，仅回移官方修复的递归深度传递与 32 层拒绝；版本使用 `0.3.45+seata.1` 明确维护身份，不冒充官方 0.3.47，不删除 RFC 2822 功能或仅限制上层输入长度。

## 行为与兼容性

沿用官方修复：注释递归从深度 1 开始，在进入第 32 层前拒绝；31 层仍接受，32 层及更深返回解析错误。空白、折行、转义括号、普通/连续浅注释、正常 RFC 2822 日期、原精确秒与时区语义保留。修复位于所有相关公共解析入口共用的原组合器，不只修补 rbatis 调用点；serde 的 RFC 2822 与可选值入口同样必须有界。

正式根工作区与 rbatis 独立探针都明确选择同一个维护副本，锁文件可追溯。补丁只涉及维护版本标识与原 RFC 2822 模块；原许可证、完整公开 API、其他解析器和依赖版本保留。`SEATA_PROVENANCE.json` 记录原归档及每个原文件/维护文件摘要，`SEATA.patch` 保留完整差异。下游发布必须显式采用维护补丁，根 patch 不自动继承。

## 证据要求

1. 补丁实施前，用独立进程和固定小栈复现原 0.3.45 的实际栈溢出，不让崩溃终止验证运行器；六个公共日期/时间/时区入口分别记录退出状态和标准错误。
2. 同一输入、同一测试源码和栈大小，在两版 Rust 的维护版本中返回解析错误并正常退出。不得以跳过危险用例或提高栈大小作为通过依据。
3. 两版检查普通值、31/32 层边界、巨大嵌套、转义与折行、连续浅注释、畸形输入和 serde；保留全部原始输入摘要与运行结果。
4. 两版工作区回归与 rbatis 八项兼容测试继续通过；确认正式 MySQL 的正常依赖边界不因此引入 ORM。
5. 执行原 RustSec 快照审计，不设置 ignore。另审计未修改上游版本的原锁文件，保留原告警对照。当前审计工具没有为维护版 path 依赖返回原 time 告警，因此不能将该退出码 0 当作源码安全证明；必须单独绑定源码、官方修复与崩溃/修复证据。保留其他漏洞和 unsound 警告，不伪报完整生产安全门禁通过。

rbatis 正式事务执行器、真实 MySQL/原 Java TC 联试、WP05/WP07 与 Phase 5–7 仍按原完整计划继续交付。
