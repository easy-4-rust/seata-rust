# Phase 3：正式 AT 并发负载验收

本项细化原架构计划 Phase 3 的并发与压力测试，以及 WP07 的负载要求。规格事实源仍为原架构计划与 V1 验收清单。本地有限负载不等于生产容量认证，也不关闭 WP05、WP07 或完整计划。

使用固定原 Java TC、真实 MySQL 和正式 Rust TM/RM，分别以 1、4、8 个同时在途事务执行八轮。两个 Rust 工具链分别执行。所有写入使用显式实验特性，保持生产默认配置不变。

每个事务在独立行上执行 UPDATE、INSERT、DELETE，生成同一分支的真实 Undo 并原子提交、报告。每轮在所有本地提交完成且全局结束前同步暂停：独立连接必须见到所有原分支、Normal Undo、原 SHA-256、提交见证、报告门闩和各自三个锁键。此屏障用于证明实际重叠，不把配置并发数视为实际并发。

释放屏障后，事务按编号交替提交、回滚。必须逐原身份核对业务行、Undo 删除或防悬挂状态、持久分支终态、日志 Completed；原 TC 的全局、分支和锁最终释放。Finished 只证明清理，不能单独证明业务结果。原始 TM/RM 帧须核对每笔仅一次 Begin、登记、报告和结束，原回调与成功响应保持相同身份和关联号。

记录实际 wall time、每笔时间、p50/p95/p99、吞吐和操作数；不设未经批准的性能 SLA。源文件、原 JAR、构建产物、原始帧、独立 SQL 与容器身份须绑定哈希。运行器只操作其创建的容器和专属库，清理进程与容器，保留证据和绑定数据。


选定矩阵已验证：双 Rust 共 208 笔，120 项证据削弱拒绝；[现场与测量](evidence/at-concurrent-load/README.md)、[ledger](at-concurrent-load.json)。本地有限负载不关闭生产及总阶段门禁。
