# 原 TC 单向 Undo 保留期清理

延续 WP05/07 和已记录的 111 消息缺口，固定 Java 来源为 `cba73e180fd8896a99df6415b859d275122feaa7` 的 RMHandlerAT、DateUtil、MySQLUndoLogManager。本增量不改变原 Undo 格式、摘要和恢复记录。

原 TC 在已登记连接发送单向 UndoLogDeleteRequest（111）。RM 只对该原连接消息取得不可手工构造的清理能力，按 branch type 和原资源 ID 查找真实处理器。合法单向请求没有响应；未知资源或不支持的资源返回本地错误并记录，不因合法清理消息关闭正常连接。同步/其他消息形状不取得该能力。

MySQL 路径按固定 UTC 参考配置实现原语义：非正保留天数回退到 7，正 i16 天数原样使用；在请求开始按客户端 UTC 日历取零点并减去天数，整个请求保持同一分界。`log_created <= cutoff` 包含边界，删除所有过期状态（包括 Normal 和 GlobalFinished），不改为只删除围栏。每批最多 3000 行、每批原事务提交，满批继续；整体绝对期限限制工作。超时/驱动失败可能保留已提交批次或未知批次，不承诺零效果，不自动重放业务，不修改恢复历史记录。

每批在关闭取消后连接复用的控制事务中核验原实例 UUID、schema、可写状态及明确 UTC 会话，沿用原 Undo 表当前结构/引擎/约束核验，并满足数据源已启用的资源/JDBC 配置绑定。TC 只提供资源查找键和保留天数，不提供 SQL、表名或任意截止时间。

验收覆盖原单向分派且同一连接可继续回调、无响应/未知资源/非 AT/非法形状、默认天数与 UTC 零点、恰好边界及微秒后保留、过期两种状态和新行、超过一批、重复指令、取消与错误、实际表/权限拒绝及原 Java 差分。清理策略须与部署方 TC 最大事务/恢复保留期一致，过期 Normal 被删除是原 Java 的保留期语义，不证明该分支已经成功结束；生产运维总门禁仍保持开放。
