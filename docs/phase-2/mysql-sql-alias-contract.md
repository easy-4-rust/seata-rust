# MySQL 单表 SQL 别名

延续原架构 9.3 的 SQL 别名要求、WP05 的能力扩充规则，补齐原 Java MySQLUpdateRecognizer/BaseMySQLRecognizer 单表别名和限定列引用。规格事实源仍为 WP05，本契约是其增量，不修改完整 Java SQL、JOIN/子查询及生产准入门禁。

UPDATE 和单目标 DELETE 支持显式 AS 与省略 AS 的单个安全 ASCII 别名；保留原 SQL 字节实际执行。实际表名用于元数据、锁键及原 Java Undo；别名只用于当前语句解析及原前镜像查询 FROM 子句，不能进入持久表身份。UPDATE 左值列可以无前缀或匹配当前别名的两段限定名；右值和 WHERE 同样只允许当前表引用。无别名时可使用实际表名作两段限定；有别名时只允许原拼写别名。未知前缀、三段跨 schema、列别名列表、JOIN/多表及原不支持表达式继续整句拒绝。重复赋值列按去掉合法前缀后的真实列名检查。

前镜像的两次读取必须使用同一合法别名及原 WHERE 绑定切片，不能只放宽 AST 而使镜像读取遗漏限定名。后镜像仍按完整真实 PK 集合读取，SQL 只执行一次；原 SQL、占位符次序、元数据主键更新拒绝、行数预算、同事务 Undo/SHA/提交见证、锁和二阶段补偿约束保持生效。词法等价检查只允许该位置省略 AS，不放宽其他 token 丢失。

验收先以分类和前镜像回归暴露缺失，再运行双 Rust 1.99/1.85 的正式提交/补偿与原 Java Undo parser 差分；覆盖有/无 WHERE、SET/WHERE 参数、合法限定、重复列与未知前缀拒绝。选定别名通过不证明完整 Java SQL 迁移或生产 V1 已完成。
