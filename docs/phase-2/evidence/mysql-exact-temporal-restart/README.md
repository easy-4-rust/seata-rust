## 实际执行与来源

Rust 1.99/1.85 × 配置 5/6 × 提交/回滚，共 8 笔全局事务、48 条 DML，运行 24 个 Rust 进程实例。每例由一个 TM 测试父进程持有全局事务，第一阶段生产者独立提交/报告后被强杀，再由不同 PID 的独立 RM 进程读取原持久分支。Windows CIM 与保留的 OS 句柄核对父子关系、实际可执行文件与 SHA、生产者已终止及最终退出码；RM 原始帧证明回调经新 TCP 连接到达替代进程。

DATE 普通列取 13 个物理行：1000/9999 上下界、1500 年日历、1582-10-04/05/10/14/15/29、纪元两侧、2000 闰日和 SQL NULL；首行其他 DATE 列保留上下界与日历切换缺口，并进入实际 UPDATE 补偿镜像。TIME(6) 主键保留 `-838:59:59.000000`、负一微秒及上界，实际 UPDATE/INSERT/DELETE 覆盖负微秒、超过一天的负时长及上界删除，验证真实临时键表、参数、锁键与恢复。TIME FSP 0–6 普通列和 DATE 主键的现场由前一增量提供。

## 同一分支上的拒绝与恢复

```mermaid
flowchart LR
    A["第一阶段原子持久化<br/>Undo 与 SHA"] --> B["核实 OS 身份后<br/>强杀生产者"]
    B --> C["合法日期等长改写<br/>保留原摘要"]
    C --> D["独立 RM 恢复检查拒绝"]
    D --> E["原 TC 实际回调<br/>分支可重试失败"]
    E --> F["观察真实回包后<br/>恢复原始字节"]
    F --> G["原 TC 自然重试<br/>同一分支完成"]
```

父进程保留数据库原 Undo 字节与摘要，将一处 `1582-10-14` 等长改为合法 `1582-10-15`，两份 JSON 均能解析，摘要不同。新 RM 进程的原提交观察与提交恢复均明确返回 `UndoChecksumMismatch`。原 TC 的实际回调随后返回分支可重试失败；只有独立观察器核对同一 XID/BranchId、方向、请求/响应相关性和活跃 OS 句柄后，才签发恢复原字节的门闩。

恢复前数据库仍保存改写字节，`terminal/commit_terminal` 均为零。恢复操作逐字节读回确认原 Undo，并保持原 SHA。原 TC 自然重试后，同一分支最终完成；没有重新登记分支、重发第一阶段报告或伪造回调。原始帧、checksum 事件、持久终态、业务最终值、日志 Completed 以及 TC 全局/分支/锁清理共同核验此过程。

实际拒绝采用 RPC Success + BranchStatus 6/9（可重试失败），完成采用 5/8。第一轮 `java_20261128_113733_65e8a413` 的观察器误要求 RPC Failed，导致门闩未释放并超时；该诊断保留完整失败帧，不计验收。修正后的选择器另有 11 项实际/构造输入检查，包含错误身份、无回包、无关联、反向顺序及成功分支不得放行。
