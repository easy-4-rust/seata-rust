本目录验证固定 MySQL 8.4.13 的选定 X509 客户端认证配置。

MySqlOptions::with_tls_client_identity_pem 将 PEM 证书链与未加密私钥成对配置，两者各有 64 KiB 上限。配置阶段解析 PEM，私钥采用固定驱动的首个 PKCS#1/PKCS#8/SEC1 块语义；DER 和证书/私钥匹配在握手时验证。客户端身份保留服务端 VerifyIdentity，并与关闭 TLS 双向互斥。Debug 和公开错误不展示私钥正文；不承诺原始 Vec 或驱动内部副本的内存零化。

red.log 是缺少公开配置方法的编译 RED。纯配置测试覆盖空值、上限、超限、无效包装、加密私钥拒绝、配置顺序及 Debug。已有 CA 配置和根证书验证测试一并回归。

自有账号 mtls_fixture 使用 REQUIRE X509、缓存 SHA-2 密码、schema 业务/元数据权限及当前实现需要的全局 PROCESS 权限。服务器只允许加密 TCP。真实 Rust 测试拒绝缺证书、其他 CA 签发的客户端证书、与证书不匹配的私钥及错误密码。正确身份经过数据源初始化、池连接、元数据辅助会话、业务 UPDATE 和 ROLLBACK，独立查询确认原值。

独立 MySQL CLI 使用 VERIFY_IDENTITY、客户端证书与私钥，记录实际账号、强制加密、TLS 1.3 和原值；同一账号只带正确 CA、不带客户端身份时返回 1045。移除 connect_options 中两个客户端身份设置的实际削弱控制在正向认证断言失败，随后精确恢复原源码并重跑正常测试。

证书由自有 CA 现场签发，服务端 IP SAN 为 127.0.0.1，客户端证书 EKU 为 clientAuth，有效期两天。仅公共证书归档，所有测试私钥保留在 D 盘夹具目录。重现时需在新目录重新生成证书并更新环境路径。根 TLS 回归也在此服务器运行。

本轮没有新增依赖版本或改变既有默认 TLS 行为。全量构建前核对绝对路径，仅清理任务构建缓存中两天以前的 30 份 PDB，清单保留，其他源码、数据和证据未删除。

此证据覆盖 RSA/选定 PEM 与直接 X509 账号配置。证书生命周期、轮换/吊销、其他算法及证书链、生产最小权限与其余 V1 门槛继续按原计划验收。
