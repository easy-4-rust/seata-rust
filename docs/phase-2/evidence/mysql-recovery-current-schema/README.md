# WP05 恢复表当前定义校验

规格事实源延续 WP05 与 mysql-commit-preconditions-contract.md，无新规格体系。

真实 RED：原业务事务取得元数据快照后，将恢复表改为 MyISAM。旧代码仍返回提交前仲裁成功；进程退出后独立查询得到业务 0、Undo 0、first_phase_committed 1、phase 0、terminal 0。该伪见证与业务原子性不一致，原始日志保存于 red.log、red-database.log。

修复在原事务 MDL 下，用原认证与 TLS 配置创建独立元数据事务，核对同实例/schema 后重跑现有恢复表规范。原快照和新事务的能力版本不一致也拒绝。元数据事务回滚关闭；提交前仲裁、恢复控制、独立见证观察使用同一入口。失败保留真实登记回执并关闭原业务作用域。

现场矩阵覆盖迟到 MyISAM、更新触发器、主键删除、资源列宽变化、不可见列、CHECK 和分区七类变更，以及合法 003→004 迁移跨旧快照。拒绝后原业务、Undo、见证和非事务触发器副作用均为零。原恢复登记行保持未绑定、非终态。MySQL 原错误 1412 同样是明确拒绝，测试不将其误判为成功。

双工具链与运行环境清理结果由 verify.py 严格核对后写入 ../../wp05-recovery-current-schema.json；日志保留每个实际测试结果。run-live.ps1 串行使用自有数据库，每套工具链/测试组使用新的本地日志目录，RM 子进程由对应工具链构建。受控原包协议对端不替代原 Java TC。夹具用户在两次恢复测试组之间显式重置，reset-fixture-user.log 留存本次重置记录。首次 MSRV 准备测试因前一工具链留下的自有 `_other` 库而失败，原日志保存于 1.85-first-preparation-fixture-conflict.log；运行器补入精确自有库和夹具用户重置，resume-msrv.ps1 重跑受影响与后续组，不修改生产断言。

独立只读审查未发现阻断项。1412 分支允许安全拒绝；合法迁移用例不单独声称 Rust 版本差异判断分支已执行。

辅助校验每次增加一个池外连接，DDL 排队可能导致按原绝对期限安全失败；要求稳定单主路由，不能据此声称支持任意复用代理。显式迁移仍要求停止旧写入器。公开业务 COMMIT、原 TC 锁安全和原 WP05/WP06 全部计划门槛仍未关闭。
