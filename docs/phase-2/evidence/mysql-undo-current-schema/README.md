本轮将既有 Undo 表结构规范在同身份新会话中复核，避免原业务事务旧字典快照漏过后提交的 DDL。

真实 RED 在业务 INSERT 建立字典快照后给 undo_log 添加 AFTER INSERT 触发器，该触发器写入 MyISAM 副作用表。旧 flush 返回成功；原事务 Drop 后独立查询得到业务 0、Undo 0、副作用 1。对应 red.log 与 red-database.log。

flush、prepare_fence 和 delete_committed 三个中央入口接收原连接配置，先执行原校验以保留原错误优先级和 MDL，再复用 CurrentTableConstraints 的实例/schema 核对连接流程。新连接在独立事务中执行同一既有引擎、七列、唯一身份索引和约束校验，完成后 ROLLBACK 并关闭。此事务只用于元数据，不写业务或发布分支结果，原事务一直保留 MDL。辅助校验不递归再建连接。

七组现场拒绝覆盖迟到触发器、唯一索引删除、VARCHAR 宽度变化、不可见额外列、无符号列及入向/出向外键。各例核对预期错误、污染作用域和回滚后业务/Undo/副作用表均为零。当前结构变化的用例与原引擎变化用例一并保留。

Rust 1.99、1.85 各运行写入 12 项、补偿 16 项、围栏 9 项和选定提交清理回调 1 项，全部通过。提交回调对端是受控原包 TCP 夹具，不冒充固定 Java TC 完整联试。测试输出目录按版本/套件/时间创建，各套件在唯一自有 MySQL 运行器中顺序执行。工作区另通过 635 项普通测试及严格 Clippy，194 项环境测试在普通运行中忽略。

原绝对期限覆盖连接、检查、辅助回滚与关闭。错误、取消及期限保留原污染/关闭策略，直接拥有的辅助连接不会回到业务池。每次活动校验增加一个池外连接。排队中的 DDL 可能使辅助 MDL 等待与原锁形成等待链，由原期限安全失败，不能声称并发 DDL 下无超时。稳定单主路由要求保持，不认证任意代理切换。

本轮重新执行已有结构规范，没有把所有 schema 扩展都定义为安全。恢复表元数据快照、原 TC 安全及公开一阶段提交等原计划门槛继续实施。自有 MySQL 使用固定镜像和 64 MiB redo，原七列日志 DDL不变。
