# 统一客户端入口契约

规格事实源：架构计划 §5.3 的 `seata-client`，以及 V1 验收清单 WP07 的配置一致性、关闭与 TLS 条目。本契约细化该入口，不改变 ADR-0008 或已有事务引擎。

## 可观察行为

1. 显式选择 TM、RM 或两者；未选择角色时，在创建任何网络任务前拒绝。
2. 显式选择明文或 TLS；没有默认明文回退。两个角色使用同一连接配置、登记身份、请求/登记预算和 TLS 信任配置。
3. 请求、登记、回调预算必须为单调时钟可表示的正数；回调并发 1..4096、批次 1..256。全部入口校验先于角色启动。
4. RM 使用调用方提供的原 ResourceCatalog 和独占 FileBranchStore，不复制 AT/XA/TCC 引擎或业务连接池。先启动 RM，再启动 TM；TM 启动失败时等待 RM 关闭并保留原错误及清理错误。
5. 构建成功表示本地拥有者已建立，不表示 TC 已登记成功。连接、登记、未知结果和业务重试仍遵循现有底层契约。
6. 消费入口关闭时先尝试 TM、再尝试 RM；TM 关闭失败不能跳过 RM。保留两个独立错误。等待复用各管理器既有预算，不发送业务 Commit/Rollback，不删除 Pending 记录。
7. 取消构建或关闭、丢弃入口时，原拥有者的 Drop 关闭网络并保留日志。TM 通过借用返回，防止持有活跃借用事务时消费入口。RM 客户端克隆在原管理器关闭后失效。
8. 公开 Debug/Display 不输出登记凭据、业务字段或嵌套底层错误；错误原因通过显式只读访问器供受控诊断使用。
9. 默认正常依赖图不引入数据库或 ORM；TLS 为可选功能，同一源码验证 Rust 1.85 与 1.99。

## 验证与边界

覆盖角色矩阵、无角色/无传输/非法预算零拨号、实际 TCP 原生登记身份一致、关闭断开及日志锁释放、持有租约时有界关闭失败、部分启动失败清理和错误脱敏。原 Java TC/数据库联合验证需要独立运行证据，受控 TCP 测试不能替代该证据。

本入口不自动选择恢复方向、不签发恢复权限、不认证全部写入器、不开放实验性 changed COMMIT。WP05/WP07 和 Phase 0–7 的其余验收继续有效。
