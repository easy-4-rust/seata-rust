# MySQL 自增主键与原始回执定位

延续 WP05 与 SeaORM 适配契约，不创建第二套规格体系。正式 AT 允许只有一个整数 AUTO_INCREMENT 主键的 InnoDB 表。元数据保留真实自增属性并同时核对 RR 字典快照与当前 SHOW CREATE TABLE，新增/移除属性不一致必须拒绝；复合主键自增、非主键自增、生成列/触发器/外键仍拒绝。旧八参数列构造默认非自增，Java Undo 格式与旧记录语义保持。

单行 INSERT 缺省自增主键或经同服务器类型赋值得到 NULL，使用原业务 OK 回执中的非零 ID 构建精确键并读取同事务完整后镜像。有符号/无符号值域须检查，不把 u64 转 i64 截断。显式零按原会话 NO_AUTO_VALUE_ON_ZERO 决定是否生成；新增明确启用该模式的配置，默认保持既有严格会话。不能猜 MAX/连续 ID/步长或用后续会话 LAST_INSERT_ID 代替原回执。显式完整键批量 INSERT 保留；需要生成键的多行语句在执行业务 SQL 前明确拒绝。

自增计数不属于事务回滚保证；允许真实服务器留下编号空隙，不通过重置计数器假装原子性。补偿恢复显式主键零时必须保持零，不能在默认模式下重新生成；内部补偿会话只为原镜像恢复启用 NO_AUTO_VALUE_ON_ZERO，原租约关闭策略不得泄漏状态。

验收包括真实 MySQL 的非单位步长/偏移、其他连接已分配主键、缺省/NULL/零/表达式零/显式键/显式批量、有符号及超过 i64 上限的无符号值、UPDATE/DELETE 的自增表镜像、零键恢复、多行/复合主键拒绝与写计数未增长、双向属性 DDL 快照变化拒绝。Rust 1.99/1.85 在未修改 Java TC 下执行提交与补偿，独立 SQL、原协议锁/登记/回调、同事务 Undo/SHA/见证和原 Java parser 均须核验；默认提交、生产准入与完整 ORM/SQL 仍按既有计划继续。
