# TCC 写入进程与同库恢复验收

规格事实源为 [TCC contract](../../../phase-2/tcc-contract.md) 的“写入进程强制终止与同实例数据库恢复”，对应总架构 Phase 4。此增量扩充验收夹具与工具，没有改动生产组件、公共 API、迁移、Java Undo 格式或既有 AT/XA 数据。

## 实际场景

两种 Rust（1.99、1.85）分别执行下列九个写入者强杀边界，并分别保持数据库运行、正常重启数据库、SIGKILL 后启动同一数据库，共 54 个场景。正式 RM 与实际 MySQL 执行 TCC；本矩阵的登记/回调对端为固定 V1 协议测试对端，不能计作原 Java TC 崩溃联合测试。

| 强杀边界 | 故障时独立可见状态 | 新 RM 处理同一原分支 |
|---|---|---|
| Try DML 未提交 | Fence、业务均不可见；原行有排他锁 | 原 Cancel 建立 SUSPENDED，未提交业务回滚 |
| TRIED 后原 Confirm | TRIED，业务 7 | COMMITTED，业务 14 |
| TRIED 后原 Cancel | TRIED，业务 7 | ROLLBACKED，业务为空 |
| Try 原 COMMIT OK 被扣留 | TRIED，业务 7 | 原 Confirm 完成，Try 不重放 |
| Confirm DML 未提交 | TRIED，业务 7；原行有排他锁 | 旧业务更新回滚后，新 Confirm 一次提交 |
| Cancel DML 未提交 | TRIED，业务 7；原行有排他锁 | 旧删除回滚后，新 Cancel 一次提交 |
| Confirm 原 COMMIT OK 被扣留 | COMMITTED，业务 14 | 复用原终态，不再执行业务 |
| Cancel 原 COMMIT OK 被扣留 | ROLLBACKED，业务为空 | 复用原终态，不再执行业务 |
| 空 Cancel 原 COMMIT OK 被扣留 | SUSPENDED，业务为空 | 复用空回滚屏障，不执行业务 |

## 证据与校验

原写入者由父测试实际创建并通过自有句柄强制终止、等待退出。独立 Python 运行器另行持有只读 Windows 进程句柄，现场确认强杀前存活、强杀后非成功退出；不按文件/PID 猜存活，也不按外部 PID 杀进程。子进程有自身退出期限，父夹具退出时会清理自有句柄。

各阶段保存独立 SQL 在强杀前、强杀后、数据库恢复后、分支恢复后的 UUID/Fence/业务；重启时检查同一容器 ID、镜像、挂载和原实例 UUID。数据库原始 COMMIT/OK 由代理截留，未提交边界通过真实 NOWAIT 锁冲突确认。恢复前后的业务 DML 分开导出；重启前先封存 general_log，恢复阶段重新计数，避免将非事务性日志表的崩溃持久性当作业务持久性。回滚的未提交尝试保留在前半段日志，不能误计为已提交业务重放。

新 RM 使用新数据源、重开旧日志；终阶段的旧 Pending 必须保留。最后逐条校验原日志的 CRC、序列、原 XID/BranchId/TCC 模式/方向/应用上下文，以及一次 Pending 到 Completed。每个分支再收一次重复回调，独立 SQL 与业务 DML 必须仍符合表中结果。

[本轮 ledger](../../mysql-tcc-process-database-recovery.json) 列出最终源码封存和全部运行证据。双版本各 791 passed / 384 ignored / 177 成功测试汇总，严格 TCC/XA/MySQL Clippy 通过。默认忽略的环境测试由本轮各运行器显式选择执行。新矩阵的 642 项证据削弱均被拒绝；常规 MySQL、正常原 Java TC 和回调故障回归另行验收。

常规回归共 16 项 MySQL、4 项正常原 Java TC、8 项原 TC 回调故障事务；连同相应证据削弱共 902 项拒绝。一次原 TC Rollback 在旧会话关闭前自然重试，产生第三个原回调；其中旧会话的一个请求因故障关闭未答复，新会话重新登记后收到同一分支的终态答复。校验器逐一检查身份、上下文、唯一关联号、关闭前时序及新会话登记，不能把未答复请求算成功。已增加针对错误会话、缺失新登记、伪造时序与重复关联号的反例；实际原报文和数据库证据保持原字节不变。此前一次 Windows 端口绑定失败的批次及过严固定回调数量的诊断保留在 validation 目录中，均不计作通过证据。

## 验收边界

进程/数据库矩阵证明选定原分支、单实例与同一数据目录恢复，不证明故障转移到不同 MySQL 实例、原 Java TC 与数据库同时崩溃、多副本拓扑或所有并发时序。动态上下文报告、完整故障矩阵、生产权限/保留清理/负载/运维、AT/XA 剩余门禁和 Phase 5–7 仍未完成。完整 TCC 和总计划门禁继续开放。
