# 真实 Go AT：RAFT 自然回滚超时与领导切换

规格事实源继续为现有Markdown/ADR、REC-TIMEOUT-003/004/009及独立恢复候选计划。Brownfield增量验证，不初始化规格工具、不改变正式WP依赖、不改原参考或既有封存输入。本轮组合已认证的前导、超时保留和异步reload观察候选；不新增生产修复。

使用原完整Go AT业务与实际MySQL accounts/undo_log，SDK经自有透明分片代理连接当前真实RAFT领导者。原TM只发送一次Begin/Rollback；阻断真实二阶段回滚请求，由原TC调度自然产生17，禁止注入会话、改写状态或合成业务回复。

验收步骤：

1. 三个原JAR TC组成真实JRaft quorum；开始SDK前确认唯一当前领导、真实JRaft/Seata任期一致、该任期异步reload成功、全副本applied追上committed；重复采样防止跨领导读取。
2. 自然17后真实SQL余额900、原完整Undo保留；各副本同XID/分支/资源/锁键/应用上下文/状态，锁不可用且不会自动继续重试。保存原RPC、SQL、控制台、原生查询及副本只读证据。
3. 各节点完成真实snapshot；停止原领导，剩余两节点选出不同领导且任期增加，成功reload保留原17/分支/锁。重启业务MySQL与SDK，人工恢复真实补偿至1000/Undo空，丢弃原成功回复，TC继续保留17/原分支/锁。
4. 原领导使用其原磁盘目录重启，确认实际snapshot加载并追上副本；再停止当前领导，发生第二次实际选举，重复当前任期成功检查。再次重启MySQL/SDK，重放同分支，余额仍1000、仅真实防悬挂Undo=1/{}，TC清理会话/分支和锁。
5. 再恢复停止节点，三个副本均观察到最终清理；两次领导切换不能用进程存活或HTTP200代替，恢复检查必须绑定当前真实任期和peer identity。原生观察仅注册TM与查询101/15/21，不发事务变更。
6. 只读观察入口不提供seed或事务变更接口；只开放实际snapshot/JFR诊断操作。生产覆盖类须与认证父字节一致，来源、源输入/依赖/SDK/原JAR/配置前后认证，记录原生帧、原始日志与自有磁盘数据；退出只停止自身资源。

先用负向测试暴露缺失/过期reload、不同原身份/副本、锁泄漏、伪选举等不可接受证据，再实现校验并实际运行。已有归一化业务检查完整复用，FILE专属journal门禁由真实RAFT副本/选举/snapshot门禁替代，不把FILE日志称作RAFT恢复证明。
