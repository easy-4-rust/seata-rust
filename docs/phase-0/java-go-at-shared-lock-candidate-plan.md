# Java / Go AT 共享锁：显式兼容候选

Brownfield增量，沿用GO-AT-RESOURCE-ID-001、ADR-0008、V1 MySQL AT边界及[真实参考缺陷](evidence/local-java-go-at-shared-lock/README.md)。规格事实源为本文及已有Markdown，不初始化新体系、不调整WP依赖、不修改固定原参考或既有认证候选。

在独立Go0001–0006认证副本之上形成0007候选，新增显式`OpenJavaATMySQL(dsn, jdbcURL)`入口。调用方须提供Java数据源实际使用的JDBC URL；在任何资源注册前校验与DSN的数据库/端点匹配，按原Java规则截去查询参数，loadbalance资源中的逗号换竖线。资源标识不得由用户名/密码派生；不同凭据指向相同显式Java资源应保持标识一致。不得解析失败后回落旧DSN标识。原入口和其他数据库/XA路径保持原行为。

兼容属性在创建资源时固定，覆盖原103注册、11注册、缓存/重连、回调路由及Undo清理。禁止注册后改写ID；禁止代理改帧或业务fixture伪造资源。旧DSN命名空间不会自动迁移；上线前必须停旧发起方并核验TC待决分支/旧Undo/缓存，不允许把已有旧命名资源静默切换后称为恢复。候选现场只用新建自有数据库，旧持久状态迁移仍需单独验收。

只对该显式资源，分支注册锁键由真实前后镜像与主键元数据重建，保留表名大小写/主键次序/复合键、去重，并按Java分号连接约定编码。禁止把所有表统一大写/小写，也禁止仅换资源标识却继续发送旧大写锁键。缺少主键元数据、不确定字段或无法无歧义编码的值必须失败回滚，不能提交没有可靠全局锁的业务。Undo原序列化格式不改，不声明Java/Go互相读取对方Undo。

先以同一测试源验证旧适配行为不能满足新资源/锁键契约，再实现候选。分别验证原默认行为不变、无凭据错误、URL/参数/端点/IPv6/负载均衡、表名大小写/多表/复合主键、空行与元数据错误。完整受影响Go包回归后再接入真实Java RM/Go RM。

现场验收使用与参考相同的MySQL accounts主键：Java真实阶段一持锁后，Go显式入口对同一行必须获得原TC明确锁冲突，而非传输超时；独立SQL确认Go本地业务回滚、没有Go Undo或成功分支。先核对原Go事务已结束，再结束Java事务；随后Go另开明确的新事务能成功执行。分开验证提交与回滚、恢复与重连，不能把第一次拒绝后的第二个新事务当作盲重发原请求。

真实帧、TC记录/锁查询、原SQL/Undo、进程/类来源、源/依赖/测试字节及清理门禁分别核对。只有已实测范围可以标记通过；旧标识迁移、全部SQL/连接别名/集群拓扑、交叉Undo代偿、通用生产认证、正式Rust、完整WP00和Phase1–7仍按原计划独立验收。
