# GO-V1-FAIL-003 显式异常码适配候选

现有规格事实源仍为WP-00、ADR-0003/0007/0008；本增量不批准待确认的分阶段冻结提案，也不开始正式Rust组件。固定Java/Go提交、原版枚举、默认Go codec和原始样例保持不变。

问题不仅是fail-fast的19/20：Java19是NotRaftLeader，20是fail-fast，21–24为TransactionTimeout/CommitHeuristic/Broken/BranchPrepareFailed；固定Go的20起为TCC/Fence等扩展，含义不同。整体移动Go iota会制造新的错误别名，不能采用。

实施步骤：

1. 实际Java编码/解码覆盖25个异常码×10类事务响应，共250例，独立断言码名、结果及其余字段。
2. 在固定原版及仅应用0001长度补丁的独立Go副本上运行同一语义对照，先证明分叉；保留实际RED结果。
3. 新增显式JavaV1ResponseProfile入口，使用原生Go模型/codec，通过独立具名转换映射异常码。保持既有Go枚举0..34；Java专有语义使用不与现有值重叠的域码，并要求通过该入口转换。构造入口不修改全局registry，原默认API保持原行为。
4. 该入口只接受10类事务响应。未知Java线缆码和不能映射的Go扩展错误返回错误；不得默认Unknown或通过byte截断伪装有效码。编码前校验字段，解码前严格校验完整长度/UTF-8/结果/状态/lockable，避免原生宽松读取吞掉畸形输入。
5. 新入口通过250例字段/字节对照、未知码/Go扩展拒绝、指针/空值/非响应拒绝策略、原29/六帧与24长度样例回归、受影响Go包测试及Rust探针回归；保留执行源与来源闭包，完成只读审查。

API范围仅序列化的事务响应payload，不含TCP帧/连接或自动peer协商；注册响应、普通请求、合并消息仍走各自已记录契约。严格入口的文本限制是非负signed-short UTF-8字节长度，超长输入显式拒绝，不复制Java超大Unicode溢出行为。原版Go、完整客户端互操作与生产Rust交付仍须分别验收。
