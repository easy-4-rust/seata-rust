# GO-V1-MERGE-001 显式合并消息候选

沿用WP-00及ADR-0003/0007/0008，保留固定Java/Go提交、原版codec registry、原样例和完整Phase0–7目标。分阶段冻结提案尚未确认，本增量不开始依赖调整的正式Rust组件。

计划分为两个连续阶段，不以第一阶段代替完整互操作：

1. **载荷阶段**：显式JavaV1MessageProfile支持原25类普通消息和59/60容器，复用0002异常码入口处理十类事务响应；正确解析无子长度前缀的消息边界、可选有符号请求ID、嵌套请求及仅结果类型容器。所有长度、UTF-8、枚举、尾部数据、深度及总节点受约束。
2. **原生传输阶段**：在独立候选副本中验证实际Getty读写路径的显式接入，覆盖完整帧/心跳/请求关联及错误传播。原版缺少codec的结论保持不变；未通过该阶段不声称Go默认或完整客户端已支持合并。

载荷阶段验收：

- 原始六个Java合并样例在未适配的Go上真实失败，不能以缺失新API的编译错误代替RED。
- 新Java38例包含25个逐类型单子消息容器、全部25消息有/无ID容器、全部12类结果、全部250异常码响应结果，以及嵌套组合，并补充有符号超时、缺省版本和null/Unknown状态；逐字段断言并捕获实际字节。
- 新入口对原29普通样例、六个原合并样例及新30例进行字段/字节验证，不能只支持两个简单子类型；全部250异常码不能在合并时退回直接cast。
- 编码/解码对称限制8MiB载荷、每容器1024子项、总2048节点、深度8；这些是候选限制，不声称Java同样限制。
- 负例覆盖截断/多余字节、错误计数/长度/ID尾、请求混入结果、未知类型/枚举、非法UTF-8、循环/深度/预算耗尽、无法保留字段及超长输入，禁止panic或静默部分对象。
- 原codec/bytes/errors包、0001/0002回归和Rust独立探针一起执行；保留源码闭包、补丁依赖、真实RED/GREEN、失败尝试、审查和运行限制。

普通字段的空值按既有Java线缆契约处理；Go模型无法区分但线缆也未区分的nil/empty字节切片可归一化，不能扩展为字符串/版本字段的通用缺省规则。编码必须防止原生codec静默截断或直接cast丢失语义。未知/未支持消息明确返回错误，不改写原始认证样例掩盖差异。

审查补充：GlobalBegin超时按Java有符号int处理；注册响应原生Version保留原始线缆值，RegistrationVersion返回独立WireVersion选项及Java getter值（需明确Java版本上下文）；ReportStatus显式区分255缺省与0 Unknown。不得把原始空Version字段当成Java getter空值。
